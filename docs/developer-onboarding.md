# Подключение второго разработчика и его ChatGPT

Актуально на 16 октября 2026 года. Проект уже реализован до локального preview G1; продолжать существующий код.

Репозиторий: https://github.com/kd1rexz/lending_total.stream-.
Общая ветка разработки: `codex/total-stream-landing`.
Последние правки интерфейса: T29–T30, коммит `f532b6b`.

## Что нужно передать разработчику

- Ссылку на репозиторий и название общей ветки выше.
- Доступ со своего GitHub-аккаунта: для закрытого репозитория нужен доступ на чтение, для отправки своих веток — права collaborator/write. Владелец добавляет GitHub username в настройках репозитория. Для публичного репозитория чтение доступно без приглашения.
- Установленные Git, Node.js **24.15.0** и pnpm **11.25.0**. Node закреплён в `.node-version`, pnpm — в `package.json`.
- Отдельную локальную папку проекта и редактор с доступом ChatGPT/агента к этой папке и терминалу. Ссылка в обычном текстовом чате сама по себе не даёт агенту доступ к файлам компьютера.
- Конкретную задачу и список файлов, за которые отвечает второй разработчик, чтобы два человека не меняли одновременно одни и те же места.

Для локального запуска не нужны API-ключи, база данных, `.env`, домен или доступ к VPS. Изображения, логотипы, шрифты Unbounded и дизайнерский PDF доступны из репозитория и зависимостей. Corsa Grotesk пока заменён системным sans; его лицензированные веб-файлы ещё не предоставлены.

## Скачать и запустить

В терминале **второго разработчика**, в каталоге, где должна появиться новая папка:

```sh
git clone --branch codex/total-stream-landing https://github.com/kd1rexz/lending_total.stream-.git total-stream
cd total-stream
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm dev
```

Если pnpm отсутствует, после установки Node: `npm install --global pnpm@11.25.0`.

Открыть **http://127.0.0.1:4321/**. Если порт занят, использовать адрес, который выведет Astro. Для изменения страницы держать `pnpm dev` запущенным; изменения применяются автоматически.

При настроенном собственном SSH-доступе GitHub вместо HTTPS можно использовать адрес `git@github.com:kd1rexz/lending_total.stream-.git`. Аутентификацию каждый разработчик настраивает в своём аккаунте; чужой пароль или токен не требуется.

Для VS Code: открыть папку `total-stream`. Рекомендованные расширения уже находятся в `.vscode/extensions.json`; команда `code .` подходит, если CLI редактора установлен.

## Совместная работа через Git

У каждого разработчика — свой клон и своя ветка задачи. Общая база — `codex/total-stream-landing`. Команды ниже предназначены для отдельного клона второго разработчика, а не для общего рабочего дерева первого.

Перед началом, при чистом `git status`:

```sh
git fetch origin
git switch codex/total-stream-landing
git pull --ff-only origin codex/total-stream-landing
git switch -c dev2/short-task-name
```

`dev2/short-task-name` заменить названием своей задачи. Оркестратор заранее назначает уникальный ID, владельца и пути записи в `docs/task-board.md`. Только оркестратор меняет доску, общие контракты и историю решений. В собственной ветке разработчик может устанавливать зависимости и запускать свои проверки; общие изменения согласовать до реализации.

После выполнения и проверок: сделать коммит только своих файлов, выполнить `git push -u origin dev2/short-task-name`, открыть Pull Request с целевой веткой **`codex/total-stream-landing`**. Указать, что изменено, как проверено и какие ограничения остались; приложить снимки экрана для визуальных правок. Отчёт задачи — `docs/reports/<назначенный-ID>.md`.

Чтобы подтянуть принятую работу другого разработчика в свою ветку задачи, сначала сохранить собственные изменения коммитом, затем выполнить `git fetch origin` и `git merge origin/codex/total-stream-landing`. Конфликты разбирать по назначенным задачам, сохраняя обе нужные правки. Не применять force push, reset/clean или массовое форматирование для обхода конфликта. Не коммитить чужие незавершённые изменения, `.env`, `node_modules/`, `dist/` и локальные QA-артефакты.

## Проверки

Первичная проверка установки и сборки:

```sh
pnpm check
pnpm test:validation
pnpm build
```

Для визуальной задачи проверить desktop и mobile, переполнение, клавиатуру и reduced motion. Автоматические браузерные проверки при необходимости:

```sh
pnpm exec playwright install chromium firefox webkit
pnpm test:e2e
```

E2E используют готовый `dist/` и поднимают отдельный preview на 4323; предварительно выполнить `pnpm build`. На Linux Playwright может дополнительно потребовать системные зависимости. Стенд компонентов: `pnpm dev:components` на 4322, проверка бюджета: `pnpm check:budgets`.

После правок запускать проверки, соответствующие изменению, и честно записывать их результат. Не ослаблять проверки ради успешного статуса. Не выполнять массовое форматирование проекта: форматировать только назначенные файлы.

## Какие данные ещё понадобятся

Для продолжения локальной разработки достаточно доступа к репозиторию и назначенной задачи. Для финального наполнения нужны реальные контакты, кейсы с медиа и разрешёнными к публикации текстами, подтверждение клиентских логотипов и финальных материалов. Для публикации нужны домен, доступ к VPS/DNS, HTTPS и ответственный за эксплуатацию. Их отсутствие не блокирует локальную работу.

Production намеренно проверяет `BUILD_CONTEXT=production`, реальный HTTPS `SITE_URL` и готовность контента. Не отключать защиту ради выкладки черновика. GitHub хранит исходники; отправка кода в репозиторий сама по себе не размещает сайт по публичному адресу.
