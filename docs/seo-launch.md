# Подготовка SEO и будущий запуск

## Текущее состояние

Контекст по умолчанию — preview. Главная и 404 содержат noindex,nofollow; robots.txt сохраняет Disallow: /, без объявления Sitemap. Индексация в этой задаче не открывалась. Отсутствие домена не заменяется localhost, тестовым адресом или фиктивным canonical.

/sitemap.xml теперь штатный статический endpoint Astro (работает и в dev), а scripts/verify-dist.mjs только проверяет результат, не дописывает файл после сборки. В preview карта намеренно пустая даже при заданном SITE_URL; она не предназначена для отправки поисковикам. В production с реальным SITE_URL содержит только главную: якоря, 404 и технические маршруты не являются отдельными страницами. Не добавляются фиктивные lastmod, priority или changefreq.

Главная сохраняет утверждённый title и описание из src/data/site.json. Дополнены Open Graph alt и Twitter Card/title/description/image; абсолютные URL изображений появляются после настройки SITE_URL. Существующие canonical и og:url зависят от SITE_URL; 404 не получает canonical. Макет, H1, описания услуг, alt изображений и содержание других секций не менялись.

Подготовлена JSON-LD Organization + WebSite только для публичной главной с доменом. Используются бренд, описание и исходный логотип. В разметку не добавляются вымышленные контакты, адрес, ИНН, отзывы, рейтинги и география. Пока preview — JSON-LD не выводится.

В футере preview размещены небольшие текстовые заглушки реквизитов (XXXXX). Они не являются данными компании, не кликабельны и исключены из production. Перед выпуском получить фактические реквизиты и определить их вывод; автоматической подстановки реальных данных пока нет.

## После получения домена и утверждённых материалов

1. Подставить реальные контакты, кейсы, реквизиты и подтвердить права/редакционные допуски. Production-валидатор по-прежнему блокирует выпуск с незаполненными данными.
2. Задать HTTPS SITE_URL основного адреса. Само добавление SITE_URL при BUILD_CONTEXT=preview не открывает индексацию.
3. На VPS настроить HTTPS, единственный канонический адрес, редирект альтернативного хоста, настоящую HTTP 404. Инструкции: docs/deployment.md.
4. До отдельного разрешения на публичный запуск оставить BUILD_CONTEXT=preview. Публичный staging закрывать Basic Auth по подготовленной конфигурации Nginx. robots/noindex не являются защитой доступа; robots Disallow может мешать роботу увидеть noindex.
5. Только при разрешённом запуске создать production-сборку. Проверить canonical /, OG-изображение, JSON-LD, отсутствие preview-реквизитов, XML sitemap с единственным действительным URL и открытый production robots. Не открывать индексацию редактированием dist вручную.
6. Проверить скорость на реальном хостинге и телефоне, затем добавить домен в Яндекс Вебмастер и Google Search Console, отправить sitemap и проверить индексирование/ошибки. Это не требует установки аналитики на страницы сайта.

## Персональные данные и оферта

Аналитика, формы, cookie-баннер, политика и оферта не добавлялись. Сам факт существования сайта не делает эти страницы обязательными. Оферта зависит от способа заключения договора; текущее приглашение обсудить индивидуальный проект не требует публичной оферты. Политика зависит от реальной обработки данных, а не от названия сайта или наличия аналитики. По T105 в подготовленных виртуальных хостах Nginx журналы запросов отключены (`access_log off`), сообщения ошибок направляются в `/dev/null`, прежний формат с IP удалён. Это ещё не применённая настройка реального VPS. Перед размещением проверить итоговую конфигурацию, глобальные/default/TLS-журналы, reverse proxy/CDN и хостинг; ранее накопленные логи не удалялись. Отключение проектных журналов не является юридической гарантией отсутствия обработки данных. Работа с обращениями по email/Telegram оценивается отдельно. Финальная правовая оценка — по реальному процессу компании, при необходимости с юристом.
