## Найденный дефект и повторная проверка

**QA-01 / P2 / закрыт.** Текст badge «Рабочий макет» поверх фотографии имел недостаточный контраст на 768 и 1024 px. Axe не мог вычислить фон из-за градиента и оставил color-contrast в incomplete. Независимая проверка изображения фона дала консервативные минимумы 3,18:1 и 2,70:1 при требовании 4,5:1 для 14 px текста. Доказательства первоначального состояния: `hero-contrast.json`, `contrast-background-{width}.png`, `contrast-input.json`.

Оркестратор добавил `.hero__preview` непрозрачный фон `var(--color-bg)`. После его новой сборки badge имеет **9,22:1 на всех шести ширинах**. Повторный независимый замер всех 64 текстовых образцов Hero прошёл: минимум обычного текста 5,08:1; крупного текста 4,04:1 при пороге 3:1. Повторные 24 reflow/axe проверки также прошли. Исправление не изменяло логику меню, данных или навигации; полный набор ещё раз без причины не запускался.

Метод `hero-contrast.mjs`: собрать фактические цвета, размеры и текстовые прямоугольники DOM; сделать только text-fill прозрачным, сохранив фон/градиент/декор; снять PNG при deviceScaleFactor=1; через Sharp, уже поставляемый с Astro, вычислить худший контраст по всем пикселям каждого прямоугольника. Такой прямоугольник консервативнее проверки отдельных штрихов глифа. Он проверяет текущую фотографию на выбранных ширинах; для новой фотографии измерение повторяется. Новые npm-пакеты не устанавливались.

Оставшийся axe incomplete для декоративной стрелки с `aria-hidden=true` относится к нетекстовому символу и не требует текстового контраста. Hero-текст на градиенте проверен отдельно указанным измерением; incomplete не был объявлен автоматическим успехом.

## Разбор первоначальных сбоев тестового стенда

Первый запуск дал 46 pass / 5 fail. До изменения сайта причины были отделены от дефектов продукта:

- Chromium/Firefox после нативного перехода `#main` оставляют activeElement=body, но следующий Tab попадает сразу на CTA внутри main. Первоначальное требование `activeElement.id === 'main'` было излишне связано с реализацией. Заменено проверкой реального пользовательского результата: следующий фокус внутри main, без повторного прохода шапки.
- В macOS WebKit обычный Tab пропускает ссылки в соответствии с платформенной настройкой. Это воспроизведено также на минимальном независимом HTML. Option+Tab проходит по ссылкам; используется только для сочетания WebKit/macOS. Достижимость, видимый фокус и Enter/Escape по-прежнему проверяются.
- В Firefox с отключённым JavaScript Promise `document.fonts.ready`, возвращённый через evaluate, не завершался, хотя синхронный `document.fonts.status` уже был loaded. Harness ждёт status polling. Проверка загрузки шрифта и no-JS сценарий сохранены.

Доказательства: `keyboard-investigation.json`, первоначальные traces/error-context в `initial-failures/`. Эти исправления не меняли код сайта и не исключали обязательные пользовательские сценарии.
