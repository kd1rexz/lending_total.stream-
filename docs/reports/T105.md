Владелец root. Изменённые пути: infra/nginx/{http,https}.conf.template, scripts/deploy/render-nginx.py; добавлен scripts/deploy/test_nginx.py. Обновлены infra/README.md, docs/{deployment,seo-launch,contracts,task-board}.md.

Запись access_log явно отключена для HTTP/ACME, основного HTTPS, alias HTTPS и staging. log_format с IP удалён. Error log этих virtual hosts направлен в /dev/null с уровнем crit: сообщения ошибок также могут содержать IP, поэтому оставлять отдельный error log означало бы неполную минимизацию. Это лишает диагностики отдельных запросов по логам; маршруты/SSL/заголовки/кеши/Basic Auth/404 не изменены.

Проверки Windows/Node24.15/Python/Chromium: python scripts/deploy/test_nginx.py — 3/3, включая production/staging × bootstrap/https с alias, отсутствие второго журнала и remote_addr, сохранение HTTPS/ACME/редиректов/404/shared assets/Basic Auth и отказ небезопасных входных параметров. pnpm test:validation — 17/17. pnpm build — успешно, 54 публичных файла, прежние warnings cases/imports. Playwright seo + not-found — 3/3, закрытая индексация и HTTP404/возврат без JS.

Попытка запустить прежний test_tools.py на Windows остановилась на импорте Unix fcntl. Существующий набор не ослаблялся; новые переносимые тесты генератора выделены в test_nginx.py. Попытка получить Linux/Nginx через установленный Docker Desktop не дала доступного Docker Engine; nginx -t/реальные HTTP-запросы через Nginx не выполнялись. Это обязательная проверка при настройке VPS, не основание заявлять, что реальный сервер уже изменён. Полный E2E/check не повторялись, UI не изменён.

Ограничения: настройка подготовлена в репозитории, но не установлена на сервер; старые логи/копии не удалялись. Глобальные журналы до выбора virtual host, default_server/TLS и внешние proxy/CDN/хостинг не контролируются этой правкой. Отключение логов не является гарантией освобождения от правовых обязанностей. По прямому поручению пользователя изменения предназначены для коммита/push в текущую ветку.
