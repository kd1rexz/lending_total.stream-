Машинный реестр файлов — `src/data/assets.json`. `scope: preview` и `status: reference` у PDF-фото не позволяют использовать его обложкой публичного кейса. Каждый публикуемый файл добавляется в реестр с источником, `scope: production`, `status: approved`, `rights: cleared` и примечанием об основании прав. Изображения кейсов хранятся в `src/assets/images/`, а `cover` в JSON задаётся относительно `src/content/`, например `../assets/images/имя-файла.jpg` (имя файла — ASCII). Само наличие флага не подтверждает права: редактор должен проверить основание до его изменения.

Логотипы компаний находятся в `src/assets/clients/`. Источники каждого файла указаны в `src/data/assets.json`; векторные знаки не набраны текстом и не перерисованы. Монохромное отображение задаётся CSS, растровые исходники сохранены без изменений.

## Как обновлять данные

1. Контакты добавлять только в `src/data/site.json`: `kind`, видимая `label`, готовый `href`. Для телефона — `tel:+` и международный номер без пробелов; для почты — `mailto:` без дополнительных заголовков; для мессенджера — HTTPS без учётных данных.
2. Услуги и кейсы редактировать в JSON collections. `id` уникален, `order` определяет порядок. У кейса указать `serviceIds`, например `["live-production", "hybrid-events"]`: соответствующие окна услуг используют те же кейсы. Кейсы остаются на главной; страницы `/cases/*` не создаются. Preview без примеров показывает пустое состояние.
3. После фактической редакторской приёмки установить `contentApproved: true` и `published: true` у утверждённых услуг/кейсов. Непубликуемые записи остаются черновиками.
4. После финальной проверки айдентики установить `brandApproved: true`. Проверить изображения, логотип, OG-изображение, шрифты, права и отсутствие reference-медиа в итоговом артефакте, затем установить `assets.productionReady: true`.
5. Выполнить `pnpm test:validation`, `pnpm check` и сборку с явным контекстом. Production потребует HTTPS-домен в `SITE_URL`, минимум один контакт, 3–4 опубликованные услуги и 3–6 опубликованных кейсов; для каждой услуги нужен хотя бы один опубликованный пример.

UI и команда выпуска используют одну функцию `loadValidatedContent()` из `src/lib/content-source.mjs`. Она читает те же файлы и те же схемы Zod, что Content Collections. `getPageContent()` получает коллекции Astro, сортирует и фильтрует записи, преобразует только нужные обложки в `ImageMetadata`.

Положительные тестовые данные находятся исключительно в `tests/validation/fixtures/`; тесты записывают их во временный каталог и удаляют его после проверки. Они не импортируются из `src/`, не являются реальными сведениями компании и не допускаются в публикуемый артефакт.

Автоматическая проверка доказывает форму данных и наличие редакторских отметок, а не истинность кейсов, права владения контактами или доступность внешних ссылок. Факты и разрешения входят в ручную приёмку T10.
